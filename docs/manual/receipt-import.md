# レシートを Gemini のチャットで入力する方法

アプリの解析（1 日 30 回までの上限）を使わずに、レシートの内容を DB に入れる方法です。
Gemini のチャット（無料）に画像を送り、返ってきた内容を、SQL にして入れます。

## 全体の流れ

| 手順 | やること | どこで |
|---|---|---|
| ① | 指示文のファイルを作る（最初の 1 回、カテゴリ表を更新したとき） | パソコン |
| ② | Gemini のチャットに、指示文と画像を送る | Gemini |
| ③ | 返ってきた JSON を、フォルダに保存する | パソコン |
| ④ | SQL を作る | パソコン |
| ⑤ | SQL を実行する | Supabase |

## ① 指示文のファイルを作る

プロジェクトのフォルダで、次を実行します。
```
node tools/export_gemini_prompt.mjs
```
`tools/gemini_chat_prompt.txt` ができます（約 32KB）。

- カテゴリ表を更新したとき（アプリ内の提案で商品が増えたときも）は、**作り直して**ください。
- JSON の分類は、**中分類の番号（M番号）と、商品名（文字）**で返ってきます（11/19 から。前は、商品の番号でした）。商品名は、文字のまま、今のカテゴリ表で探すので、表が変わっても、ずれません。
- 中分類の番号（M番号）だけは、Gemini に貼った指示文の番号です。中分類が増えたとき（例: 「たばこ」）は、番号が変わるので、指示文を作り直す前の JSON は、先に ③ で SQL にするか、古い指示文を、その JSON のフォルダに `prompt.txt` という名前で置いてください（このツールが、そちらを使います）。商品名が分かれば、中分類の番号がずれていても、商品は正しく決まります。

## ② Gemini のチャットに送る

1. Gemini のチャットを開く
2. `tools/gemini_chat_prompt.txt` の中身を、**全部コピーして貼る**（またはファイルを添付）
3. レシートの画像を送る

**ポイント**
- 画像は **1 枚ずつ**がいちばん正確です。多くても 3〜5 枚までにします。
- 商品の行だけを大きく写すと、読み間違いが減ります。
- 長い会話では、最初の指示を忘れることがあります。数枚ごとに、新しいチャットで、指示文から貼り直します。
- 高精度のモデル（Pro や「思考」モード）を選べるなら、そのほうが正確です。

## ③ JSON を保存する

1. 返ってきた JSON を、`tools/receipt_json/` に保存する（ファイル名は、何でもよい。Gemini が付けた名前のままでよい）
2. **崩れた JSON（` ```json ` や `[cite: 1]` が混ざる）は、次の ④ のコマンドが、自動で直す**

## ④ SQL を作る（1 つのコマンド）

準備（1 回だけ）: プロジェクトの直下に、`.import-uid` というファイルを作り、取り込み先の UID（Supabase の Authentication → Users）を、1 行で書く。

```
npm run import-json
```

これで、次のことを、自動で行います。
1. 崩れた JSON を直す（元のファイルは `misc/JSON元ファイル_日付/` に残る）
2. SQL を作る（レシート 45 枚ごとに分ける。`tools/receipt_json/import_1.sql`、`import_2.sql` …）
3. SQL の `ここにあなたのUID` を、`.import-uid` の UID に書き換える
4. 重なっているレシート（JSON どうし）と、商品の合計がレシートの合計と大きく違うレシートを、画面に出す

- カテゴリは、**商品名（文字）を、今のカテゴリ表で探して**入れます。表に無い商品名は、中分類までになります。
- **印字名の辞書**（分類の間違いの記録から作ったもの）に当たる商品は、辞書の分類になります。
- 店名は、アプリと同じ辞書で、「チェーン名 支店名」にそろいます。
- 同じ店・同じ購入日・同じ合計のレシートが、DB にすでにあれば、飛ばします。

## ⑤ SQL を実行する

1. VSCode で、`import_1.sql` を開き、全部コピーする（UID は、入っています）
2. Supabase の SQL Editor に貼り付けて、実行する → `Success` と出れば成功
3. `import_2.sql`、`import_3.sql` … も、**番号の順番に**、1 つずつ実行する
4. アプリのレシート一覧で、入ったか確認する
5. 終わったら、次のコマンドで、JSON と SQL を、`misc/` に移す（次回、二重に取り込まないため）
   ```
   npm run import-json:done
   ```

## すでに入れたレシートの「分類」だけを直す（更新モード）

指示文を作り直して、JSON を作り直したときに、**すでに DB にあるレシートの分類**を、新しい分類に直します。レシートは、入れ直しません（消しません）。

```
node tools/receipt_json_to_sql.mjs --update --all
```
（フォルダを指定する場合: `node tools/receipt_json_to_sql.mjs --update tools/receipt_json/appro`）

`tools/receipt_json/update.sql` ができます（`import.sql` とは、別のファイルです）。

- **同じ店・購入日・印字名・値段の明細**の、分類（大・中・小分類・商品名）だけを、新しい JSON の番号で直します。
- 店名・購入日・値段・容量・値引きは、変えません。自分のレシートだけが対象です。
- JSON に、使える商品番号が無い明細は、飛ばします（今の分類を、そのままにします）。
- アプリで、手で直した分類も、JSON の番号どおりに、上書きされます（対象は、JSON にある明細だけです）。
- 実行したあと、メッセージ（NOTICE）に、「更新した明細: ○ 件」と、DB に見つからなかったレシートが出ます。
- 2 回実行しても、同じ結果です。

## ⑤ SQL を実行する

1. `import.sql` を開いて、`ここにあなたのUID` を、自分の UID に書き換える（`'` は残す）
   - UID は、Supabase の Authentication → Users で確認
2. 全部をコピーして、Supabase の SQL Editor に貼り付ける
3. 実行する → `Success. No rows returned.` と出れば成功
4. アプリのレシート一覧で、入ったか確認する

## 二重登録を防ぐために

- **入れ終わったら、`npm run import-json:done` を実行する**（JSON と SQL が、`misc/` に移り、次回、二重に取り込まれません）
- 入れたあとに、アプリでレシートを直していると、同じ JSON をもう一度入れたときに、二重になることがあります。

## 知っておくこと

- 画像は入りません（画像なしのレシートになります）。
- 商品の値段は、複数買ったときも、**1 点あたりの値段**です。値引きは引かず、「値引きあり」の印だけです。
  - そのため、商品の合計がレシートの合計と合わないのは、普通です。
- 商品の数（読み落とし）だけは、画像と見比べて、確認します。
- アプリの 1 日 30 回の上限は、この方法にはかかりません。
