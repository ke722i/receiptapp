# レシートを Gemini のチャットで入力する方法

アプリの解析（1 日 30 回までの上限）を使わずに、レシートの内容を DB に入れる方法です。
Gemini のチャット（無料）に画像を送り、返ってきた内容を、SQL にして入れます。

## 全体の流れ

| 手順 | やること | どこで |
|---|---|---|
| ① | 指示文のファイルを作る（最初の 1 回、カテゴリ表を更新したとき） | パソコン |
| ② | Gemini のチャットに、指示文と画像を送る | Gemini |
| ③ | 返ってきた JSON を、フォルダに保存する | パソコン |
| ④ | SQL を作る | パソコン |
| ⑤ | SQL を実行する | Supabase |

## ① 指示文のファイルを作る

プロジェクトのフォルダで、次を実行します。
```
node tools/export_gemini_prompt.mjs
```
`tools/gemini_chat_prompt.txt` ができます（約 36KB）。

- カテゴリ表を更新したときは、**作り直して**ください。古い指示文で作った JSON は、カテゴリが合わなくなります。

## ② Gemini のチャットに送る

1. Gemini のチャットを開く
2. `tools/gemini_chat_prompt.txt` の中身を、**全部コピーして貼る**（またはファイルを添付）
3. レシートの画像を送る

**ポイント**
- 画像は **1 枚ずつ**がいちばん正確です。多くても 3〜5 枚までにします。
- 商品の行だけを大きく写すと、読み間違いが減ります。
- 長い会話では、最初の指示を忘れることがあります。数枚ごとに、新しいチャットで、指示文から貼り直します。
- 高精度のモデル（Pro や「思考」モード）を選べるなら、そのほうが正確です。

## ③ JSON を保存する

1. 返ってきた JSON を、ファイルに保存する（例: `tools/receipt_json/welcia/welcia_1.json`）
2. 店ごとにフォルダを分けると、整理しやすい
3. ファイルが崩れているとき（` ```json ` や `[cite: 1]` が混ざる）は、次で直す
   ```
   node tools/fix_receipt_json.mjs tools/receipt_json/welcia/welcia_1.json
   ```

## ④ SQL を作る

```
node tools/receipt_json_to_sql.mjs tools/receipt_json/welcia
```
`tools/receipt_json/import.sql` ができます。

- カテゴリは、番号から名前に直して入れます。表に無い番号は「未選択」になります。
- 店名は、アプリと同じ辞書で、「チェーン名 支店名」にそろいます。
- 同じ店・同じ購入日・同じ合計のレシートがあれば、飛ばします。

## ⑤ SQL を実行する

1. `import.sql` を開いて、`ここにあなたのUID` を、自分の UID に書き換える（`'` は残す）
   - UID は、Supabase の Authentication → Users で確認
2. 全部をコピーして、Supabase の SQL Editor に貼り付ける
3. 実行する → `Success. No rows returned.` と出れば成功
4. アプリのレシート一覧で、入ったか確認する

## 二重登録を防ぐために

- **入れ終わった JSON は、次の SQL を作るフォルダから外す**（次は新しいフォルダ）
- 入れたあとに、アプリでレシートを直していると、同じ JSON をもう一度入れたときに、二重になることがあります。

## 知っておくこと

- 画像は入りません（画像なしのレシートになります）。
- 商品の値段は、複数買ったときも、**1 点あたりの値段**です。値引きは引かず、「値引きあり」の印だけです。
  - そのため、商品の合計がレシートの合計と合わないのは、普通です。
- 商品の数（読み落とし）だけは、画像と見比べて、確認します。
- アプリの 1 日 30 回の上限は、この方法にはかかりません。
