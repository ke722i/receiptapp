# カテゴリ表（Excel）を更新する方法

商品やカテゴリを増やしたいときの手順です。

## 全体の流れ

| 手順 | やること | だれが |
|---|---|---|
| ① | Excel（`tools/categoryTable.xlsx`）を編集して、同じ場所に上書き保存する | あなた |
| ② | Claude に「カテゴリ表を更新して」と言う | あなた |
| ③ | カテゴリ表を作り直して、変更点を報告する | Claude |
| ④ | `npm run deploy-functions` を実行する | あなた |
| ⑤ | コミット → PR → マージ | あなた |

## ① Excel を編集する

- 場所: `tools/categoryTable.xlsx`
- 大分類ごとにシートがあります。並びは **中分類 → 小分類 → 商品名** です。
- 行を足すときは、隣の行と同じ形（番号・列の位置）で書きます。
- **「その他」は入れません**（アプリが自動で付けます）。
- 編集する前に、**最新のファイルか**確認してください。Claude や提案の反映で、更新されていることがあります。

## ② Claude に頼む

「**カテゴリ表を更新して**」と言うだけです。Claude が、次を行います。
- カテゴリのデータを作り直す
- 漢字の読み仮名が足りなければ、足す（ホームの検索で、ひらがなで探すため）
- 増えた・減った項目を報告する
- アプリが動くか（build）確認する

## ④ デプロイする

```
npm run deploy-functions
```
- 実行するまで、AI の解析は、古いカテゴリ表のままです。
- 実行には、Supabase へのログインが必要です。

## ⑤ 公開する

コミット → GitHub で PR を作る → `main` にマージ（アプリの画面に反映されます）。

## 注意

- 古い Excel を上書きすると、前の更新が消えます。
- 商品名を変えると、すでに登録したレシートのカテゴリとは、名前が合わなくなることがあります。

# 店名（チェーン）を追加する方法

レシートの店名を、「チェーン名 支店名」の形にそろえるための辞書に、新しいチェーンを足します。

1. Claude に「**店名を追加して**」と言う
2. 追加したい店名と、レシートに印字される書き方（カタカナ・英字など）を伝える
3. Claude が追加して、結果を報告する
4. コミット → PR → マージ

**ポイント**
- 「玉出」のような地名や短い言葉は、支店名と間違えるので、キーワードにしません。
- 別のお店として分けたいものは、別の項目にします（例: ローソンストア100）。

## 分類の間違いの記録から、辞書を作る（同じ印字名を、次から正しく分類する）

| 手順 | すること |
|---|---|
| 1 | `tools/wrongCategory.xlsx` に、間違いを書き足す（印字名、カテゴリの上の行 = 間違い、下の行 = 正しい分類。わからなければ「？」） |
| 2 | `tools/dictionary_candidates.xlsx` の、「採用」の列に、○ か別の分類を書く（使い方は、その Excel の「使い方」シート） |
| 3 | `npm run dictionary` を実行する（入る数と、入らなかった記録の理由を表示して、辞書を作る） |
| 4 | `npm run deploy-functions` を実行する（または、3 の代わりに `npm run dictionary:deploy` で、まとめて） |
| 5 | コミット → PR → マージ |

**ポイント**
- ユーザーが直した分類を、管理者が承認する仕組み（管理者の「分類の修正」）で入れたものは、デプロイ不要で、すぐ効きます。この手順は、記録の Excel から入れるときの方法です。
- 正しい分類の名前は、今のカテゴリ表にある名前（商品名・小分類・中分類）で書きます。表に無い名前（例: ケーキ）は、入りません。アプリの提案で、表に足したあとに、作り直すと入ります。
- 印字名が、ぴったり同じときだけ使います（全角半角・空白・大文字小文字の違いは、同じとみなします）。
- 同じ印字名で、正しい分類が食い違う記録は、入りません。

## 店舗名の表記ゆれを、まとめて直す

「TRIAL 阪南店」と「トライアル 阪南店」のように、同じ店が、別の名前で分かれているときの直し方です。

| 手順 | すること |
|---|---|
| 1 | `npm run fix-stores` を実行する（DB の店舗名を読んで、直る名前の一覧「前 → 後」を表示し、`tools/receipt_json/store_names.fix.sql` を作る） |
| 2 | 一覧を見て、直したくないものがあれば、その部分を `store_names.fix.sql` から消す |
| 3 | `store_names.fix.sql` を、Supabase の SQL Editor に貼って、実行する |
| 4 | アプリの「店舗」のタブで、まとまったか確認する |

- 全角と半角の違い（「（）」と「()」）、空白の重なり、店名の辞書の表記ゆれ（TRIAL → トライアル）が、そろいます。
- 直るのは、レシートの店舗名と、マイ店舗に登録した店舗名です（マイ店舗に同じ名前があるときは、飛ばします）。
- 先に `.db-readonly.url` の準備が要ります（`DB を調べる` のシート）。

## 昔の明細（中分類までのもの）を、商品まで直す

カテゴリ表に、商品を足したあと、すでに DB にある「中分類までしか決まっていない明細」を、印字名の一致で、商品まで直します。

| 手順 | すること |
|---|---|
| 1 | `npm run fix-products` を実行する（DB を読んで、直る印字名の一覧「前 → 後・件数」を表示し、`tools/receipt_json/midonly_fix.sql` を作る） |
| 2 | 一覧を見て、**直したくないものは、SQL から消す**（別の意味で、商品名が入っているだけのもの。例: 「キムチ鍋」→ キムチ） |
| 3 | `midonly_fix.sql` を、Supabase の SQL Editor に貼って、実行する（`UPDATE ○` と出る） |
| 4 | アプリで、商品詳細・購入履歴に、反映されたか確認する |

- 確かなものだけ直します。明細の中分類（AI が決めたもの）の中で、印字名に含まれる商品名が、1 つに決まるときだけです。別の中分類の商品名には、当てません。
- 2 回実行しても、同じ結果です。
- 直すのは、全アカウントの明細です。
