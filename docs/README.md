# docs の使い方

| フォルダ | 読む人 | 書き方 |
|---|---|---|
| `manual/` | **人間（管理者・開発者）** | 表・箇条書き・短い文。手順を、上から順にやれば終わる形 |
| `claude/` | **Claude** | 正確さを優先。条件・コマンド・ファイル名を細かく書く |

## 人間向け（`manual/`）

**あなたが読むのは、プロジェクト直下の `マニュアル.xlsx`（タブ分け）だけです。** 元の文章は、`docs/manual/*.md` です。直したあと、`npm run manual` で、Excel を作り直します（Excel は、Git に入りません）。

| ファイル（タブ） | 内容 |
|---|---|
| `index.md`（はじめに） | タブの一覧、ファイルの場所、困ったときの見先 |
| `commands.md`（コマンド早見表） | 自分で実行するコマンドと、Claude への指示の言い方 |
| `release-flow.md`（公開の流れ） | 公開までの流れ（コミット・PR・マージ・デプロイ） |
| `admin.md`（管理者） | 管理者の画面の使い方（利用状況・お知らせ・アカウントの管理・分類の修正） |
| `proposal-approval.md`（提案の承認） | カテゴリの提案の承認のしかた（管理者画面・CSV・表への反映） |
| `receipt-import.md`（レシート取り込み） | Gemini のチャットで、レシートを入力する方法 |
| `category-table.md`（カテゴリ表・辞書） | カテゴリ表（Excel）の更新、店名の追加、印字名の辞書、店舗名の表記ゆれ |
| `icons.md`（アイコン） | 商品アイコンの追加 |
| `db-readonly.md`（DBを調べる） | DB を、読み取り専用で調べる準備 |

## Claude 向け（`claude/`）

仕様（`spec-*.md`）、作業手順（`procedures.md`、`proposal-approval.md`、`icons.md`）、テスト項目書のルール（`test-items-rules.md`）。
Claude が、作業の前に読みます。入口は、プロジェクト直下の `CLAUDE.md` です。

## 書くときのルール

- **人間向け**: 見出し・表・番号つきの手順。1 文を短く。専門用語や、ファイル名の説明は、必要なものだけ。
- **Claude 向け**: 前提・条件・コマンド・例外を省かずに書く。
- 仕様や手順を変えたら、該当するファイルを直す（両方に関係するときは、両方）。

## misc フォルダ（手元の整理用）

- プロジェクト直下の `misc/` は、**使っていないファイル・古い作業ファイル・作り直せる Excel** を、置いておく場所です（Git には入れません。なくなっても、アプリや手順は、困りません）。
- `misc/excel/`: 画面仕様書・取り扱い店舗の Excel（`python tools/export_screen_spec.py`、`python tools/export_stores.py` で、ここに出ます）
