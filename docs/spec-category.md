# 3. カテゴリの仕組み
- 4階層: 大分類 > 中分類 > 小分類 > 商品名。元データはExcelで、categoryData.js はそこから生成したもの。
- 同じ名前の商品が別の場所にあっても混ざらないよう、商品は名前ではなく経路 {main, category, sub, product} で区別する（productKey）。
- DBの receipt_items: main_category(大) / category(中) / sub_category(小) / product_name(商品名) / item_name(レシート印字名)。
- AIには M/P コードで答えさせ、コードから名前に戻している（supabase/functions/parse-receipt/catalog.js）。
- 商品を表に当てはめられなくても、中分類まで当てはまるならそこまで保存する。
- 「その他」は Excel（表）に入れず、編集画面のプルダウンの末尾にコードで足す（categoryUtils.js の OTHER）。
  表に入れると、検索の候補や価格比較に「その他」が混ざるため。
  - その他を選んだ階層より下は選択不要で、空（null）で保存する。大分類がその他なら中分類も「その他」にする。
  - 「未選択」は AI が当てはめられなかった・まだ決めていないもの、「その他」は人が選んだもの。AI の結果を「その他」にしない。
  - ホームのカテゴリにも、編集画面と同じ階層（大・中・小・商品名の最後）に「その他」をコードで足す（Excel には入れない）。押すと、その「その他」で登録した明細の購入履歴が開く
    （「その他」の箱のパスは categoryUtils.js の otherMainPath など。空の階層は null）。マイ店舗の価格比較は出さない。検索の候補・検索履歴にも出さない。
- 値引きは「あり／なし」の表示だけ。比較は自分のレシートのみ。
- ホームの検索は、切り替え（検索バーの左のプルダウン）で「すべて／カテゴリ／商品名」。印字名は「すべて」のときだけ探す。カテゴリは CATEGORY_READING_MAP（分類名の読み）でもひらがなで探せる。
  印字名は自分のレシートの明細（fetchMyItemNames。1 回読み込んで覚え、保存・編集・削除で捨てる）。検索の処理は src/utils/searchUtils.js。
- ぴったりの分類が無い商品のために、ユーザーは「カテゴリの提案」で、新しい中分類・小分類・商品名を提案できる（設定・ホームのお知らせから開く）。
  管理者が承認したものを Excel に足して反映する（手順は「7. 作業手順」の「カテゴリの提案の承認手順」）。
  - 提案できるのは 3 種類: 新しい中分類（小分類も一緒でよい）／今ある中分類に新しい小分類／**今ある小分類に新しい商品名**（11/13 追加。ユーザーの指示）。大分類は選ぶだけ。
    承認した中分類・小分類に入れる商品名は、管理者が決める（Claude に指示して、Claude が Excel に足してもよい）。商品名の提案は、その名前を使う。
  - DB は category_proposals（migrations の 20261111000000_category_proposals.sql、20261111100000_category_proposals_categories.sql、20261113000000_category_proposals_product.sql）。
    kind は category／sub／product（product は、小分類・商品名が必須）。11/11 より前の以前の形式の product は、自動で見送りにしてあり、admin_note（notices.js の LEGACY_AUTO_REJECT_NOTE）で見分ける（「以前の形式」と表示し、通知には出さない）。登録は関数 submit_category_proposal からだけ。本人は自分の提案だけ読め、承認待ちだけ取り下げられる。status（pending／approved／rejected）は管理者だけが変える。
  - 承認待ちは 1 人 20 件まで。同じ人の同じ提案は重ねて出せない（別の人の同じ提案は、要望の多さとして数える）。
  - 位置の選択肢に「その他」は出さない。表から選んだ名前（中分類・小分類）は、そろえずにそのまま送る（NFKC でそろえると「（未調理）」の全角かっこが変わり、表と合わなくなる）。今の表と同じ名前（空白・カナの違いをそろえて比べる）はエラー、似た名前は注意。画面側の検証は src/utils/categoryProposal.js。
  - 知らせ方: ホームのお知らせ（「✕」で閉じると、その端末では出ない）と、商品の編集画面で「その他」を選んだときの案内。
  - 承認しただけでは、画面にも AI にも出ない。すでに「その他」で登録したレシートも、自動では移らない。

# 3.5 ユーザーアイコン
- アイコンは、用意された画像（src/assets/avatars/ の SVG、一覧は src/constants/avatars.js）から選ぶ。任意の画像のアップロードはできない（Storage も使わない）。
- 選んだ画像の id だけを、アカウントの情報（Supabase Auth の user_metadata.avatar）に保存する。DB の表・SQL の変更は無い。選んでいなければ「👤」。
- 画像を足す・変えるときは、SVG を置いて avatars.js に足す。保存済みの id は変えない（変えると、その人のアイコンが「👤」に戻る）。
